# Arcaea 7.0.260c offset evidence

Language: English | [简体中文](7.0.260c-offsets_CN.md)

Target: `libcocos2dcpp.so` (ARM64, stripped)

- SHA-256: `09fad9e3299acf9b68613b8418c6dcc1bd7f200e42945198f369bbf491e9ad34`
- Build ID: `7c171c3dab4cf5b73dc2b1c3e7728fc0879f09cd`
- FMOD provider SHA-256: `7f67c6940afaeaad1c05857d118e4a1d223c0a625a593369c80358e7b02d1d8c`

All 19 consumed functions were relocated from 7.0.255c with
`scripts/port_match.py`; 20 of the 21 spec targets (the songlist asset-open
body included) were pinned and re-verified in a second locate pass recorded in
`scripts/port_match_70260c_spec.json`. The relocated `ShowJudgementEffectAtNote`
keeps the 7.0.255c extent (0xAC8 bytes) and prologue. `registry_getter` is
below the matcher's voting floor, so it is pinned by exact masked bytes;
IDA independently confirmed the version global, direct call relationships,
RTTI objects, asset-loader callsite, registry global, and scenecontrol getter.

## Semantic confirmation

- The version setter at `0x1922684` copies the Java string into the libc++
  string at `0x1BE5F68` (plus a secondary copy at `0x1BEFCE0`) with the exact
  instruction shape of the 7.0.255c setter; runtime detection therefore keeps
  its existing model.
- `processLogicNotes` reads the note vector at `Gameplay +0xA0/+0xA8`, walks
  it with the same Tap/Flick/Long/Arc/Camera/SceneControl dispatch as
  7.0.255c, calls `ScoreState_applyMiss @ 0x1727198` and
  `ScoreState_applyJudgement @ 0x156EBA8`, and dynamic-casts through
  `_ZTI12LogicArcNote @ 0x1ADC2C8`. The miss-window timer reads keep the
  `+0x20/+0x28/+0x2D/+0x34` displacements of the shared Timer mirror.
- `tryTapJudgementForTouch` references both Hold and Arc RTTI objects
  (`0x1B61FA8` / `0x1ADC2C8`) and writes the hold head-activated flag at
  note `+0xA8`. ELF relative relocations bind the unique type-name strings
  `"13LogicHoldNote" @ 0x4E058C` / `"12LogicArcNote" @ 0x43FC8B` to those two
  `_ZTI` objects.
- `ShowJudgementEffectAtNote` keeps its 7.0.255c extent (0xAC8 bytes) and
  prologue; the masked-body diff against 7.0.255c is 83.2% verbatim, and both
  callers remain `note_effect_on_miss +0x11C` and
  `note_effect_on_judgement +0xB8` — the exact call sites 7.0.255c used.
- `HttpClient_processRequest` keeps the 7.0.255c request-type switch at
  `request+0x0C` (reached via `response+0x10`), the body range at
  `+0x28/+0x30`, and calls the relocated curl wrapper at `0xE1D294`.
- The tiny registry getter (`sub_165C7A8`, 0x20 bytes) reads the global at
  `0x1BE0DD0` and derefs it `+120` then `+24` — the exact chain 7.0.255c's
  getter performed over `qword_1BE7028`. This establishes the song-registry
  owner global used before `find_song_by_id`; the relocated
  `find_song_by_id` keeps its map lookup at `arg+24`. The 260c locate pass
  pins it via expect_bytes because a 0x20-byte body cannot vote.
- The scenecontrol getter is still the unique 8-byte
  `LDRB W0,[X0,#0x110]; RET` sequence in the whole binary. It sits at
  `0x83DDAC`.
- The songlist asset-open function is the relocated cocos2d-x
  `FileUtilsAndroid` asset path: the `AAssetManager_open` PLT stub
  (`0x1A624D0`) has exactly two callers, and the songlist one sits at
  `0x165A200` = function `+0x200` with the `BL; MOV X20,X0; CBZ X0` pattern
  and the `CCFileUtils-android.cpp` strings. Its extent is back to the
  7.0.1c-shaped `0x418` bytes (7.0.255c had inlined extra helpers into a
  0x744-byte body); that inlining is also why the first locate pass ranked a
  multiplayer-tutorial lookalike above it, resolved by the PLT-caller check.
- The paired gameplay, play-launcher, chart-path, and availability bodies keep
  all consumed object displacements. 7.0.260c therefore reuses the 7.0.x
  derived note layout (`isVoid +0xA4`, `activeNow +0xD0`, runtime X/Y
  `+0xD4/+0xD8`, hold-head `+0xA8`) and the unchanged custom-chart Song family
  (`remote_pack +0x1C0`, difficulty table `+0x228`, lock `+0xF0`).
- `libfmodProvider.so` still exports
  `_ZN24AudioProviderFMODAndroid7loadBGMEPKci` at `0x36AC8` with size `0x3A0`.

## Reproduce the checks

```bash
python scripts/port_match.py locate ../7.0.255c/libcocos2dcpp.so \
  ../7.0.260c/libcocos2dcpp.so scripts/port_match_70260c_spec.json
python scripts/port_match.py diff ../7.0.255c/libcocos2dcpp.so \
  ../7.0.260c/libcocos2dcpp.so scripts/port_match_70260c_spec.json
python tests/verify_profile.py 7.0.260c
python tests/run_host_tests.py
./build.ps1 --rebuild --rel
```

`tests/verify_profile.py` pins the exact binary SHA-256, all hook prologues,
the songlist callsite, both digest guards, the scenecontrol getter, and every
runtime patch word.
