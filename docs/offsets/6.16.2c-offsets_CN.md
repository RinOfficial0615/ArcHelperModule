运行时在安装前同时校验 `0x142CFAC` 的 BL 与两个 digest guard；`__cxa_throw` 与 FMOD `loadBGM` 从 ELF 动态符号解析，song registry lookup、songlist difficulty filter 和 play launcher 继续按 profile 解析，入口均校验前 16 字节。FMOD Hook 把 `file:///android_asset/songs/ah_.../base.ogg` 映射到导入缓存的真实文件路径。inline hook 采用 Register/Commit 事务，提交中任一步失败都会逆序回滚。

IDA 证实 song 构造函数只在对应 `ratingClass` 存在时写入 `song+0x228+8*class`，缺失难度只清 `song+0x250+class` 的 presence flag，指针槽保持未初始化。官方曲目至少有 0/1/2，因此未触发；Beyond/Eternal-only 自定义曲目会被固定读取 class 0 的排序/UI 路径解引用。运行时只把 presence=false 的缺失槽指向当前真实难度对象，不修改 presence flag。

定位依据为旧版本函数体、BL 调用关系、字符串/RTTI relocation 和目标入口字节交叉验证。设备 smoke 仍由用户执行。
