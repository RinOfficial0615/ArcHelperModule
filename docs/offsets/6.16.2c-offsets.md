Install-time checks cover the `0x142CFAC` BL and both digest guards together. `__cxa_throw` and FMOD `loadBGM` resolve from ELF dynamic symbols; song-registry lookup and the songlist difficulty filter still resolve from the profile. All four validate the first 16 entry bytes. The FMOD hook maps `file:///android_asset/songs/ah_.../base.ogg` onto the extracted cache file. Inline hooks use a Register/Commit transaction; any later failure rolls back already-installed entries in reverse.

IDA shows the song constructor writes `song+0x228+8*class` only when that `ratingClass` exists. A missing difficulty only clears the presence flag at `song+0x250+class` and leaves the pointer slot uninitialized. Official songs always have classes 0/1/2, so this does not fire. Beyond/Eternal-only custom songs hit a hard-coded class-0 sort/UI path and would dereference that slot. Runtime only points a presence=false missing slot at the current real difficulty object; it does not change the presence flag.

Sites were located by crossing older function bodies, BL call sites, string/RTTI relocations, and the target entry bytes. Device smoke remains a user check.
